# M6 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Phew 0.1.0: a polished CLI with help on every command, a README a stranger can install from, attribution, and a universal release zip with a SHA-256, ready to publish on GitHub.

**Architecture:** No new features. A CLI test target pins the help text; `make release` builds a universal (arm64 + x86_64) `Phew.app` with the CLI inside, zips it with `ditto`, and writes the checksum. Publishing (GitHub release, making the repo public) happens only after the user says so.

**Tech Stack:** Swift 6, swift-argument-parser, `ditto`, `shasum`, `codesign`, `gh` (only when the user approves publishing).

**Spec:** `docs/plan.md` sections 12 (CLI), 14 (M6 row), 15 (distribution). Carry list in `docs/progress.md`.

## Global Constraints

- Version `0.1.0`, build `1`. Repo `https://github.com/dika-putra/phew`. Author Dika Putra. MIT.
- Every command (`scan`, `clean`, `list`, `versions`, `config`) and the root have an `abstract` and a `discussion` with at least two examples. `admin-delete-dyld` stays hidden.
- README and help text follow the user's writing style: plain, specific, no marketing words, no emojis.
- The release zip contains only `Phew.app` (with `Contents/MacOS/PhewApp` and `Contents/MacOS/phew`, both universal), ad-hoc signed. File name `Phew-0.1.0.zip`, checksum file `Phew-0.1.0.zip.sha256` (`shasum -a 256` format). Also `Phew-0.1.0.dmg` (drag to Applications, made with `hdiutil`, UDZO) with `Phew-0.1.0.dmg.sha256` (added on the user's request).
- Nothing is published, tagged on GitHub, or made public without the user's explicit yes in chat at that moment.

## Review Focus

1. A user who downloads the zip from a browser: Gatekeeper blocks the ad-hoc signed app; README gives the exact `xattr -cr` command and explains why. Checked in Task 2.
2. A user with no project folders and no tools installed: README "First run" says what they will see and how to add a folder. Checked in Task 2.
3. `phew` from the app bundle run through the `~/.local/bin` link: `--version` and `--help` work (the binary must not depend on its own path except for `admin-delete-dyld`). Test in Task 3.
4. A cancelled `sudo` in `phew clean` for dyld items: reported as skipped, not failed. Test in Task 1.
5. Universal binary on Intel: built and verified with `lipo`, not run (no Intel Mac here). Noted in the release notes as untested on Intel.
