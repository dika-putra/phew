# M5 Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clean what needs a tool, not a plain folder delete: package manager caches (npm, pnpm, Go modules, Cargo registry), Docker, iOS simulators and runtimes, the simulator dyld cache (admin), and old SDK versions from fvm, nvm and rustup. Available in the CLI and the popover.

**Architecture:** An `Item` gains a `removal` (paths, a command, or an admin delete) and a `measure` (paths, or Docker's own numbers). `Executor` runs the removal and measures as before, so Planner, confirm view, receipt and Quick clean stay unchanged. Each tool is one small `ToolScanner` function that returns items; `AppModel.liveScan` and `phew scan` add them. Version managers read their version folders from disk (not CLI tables) and find pinned versions in project roots.

**Tech Stack:** Swift 6, `Shell`, `xcrun simctl`, `docker`, `osascript` (admin prompt), Swift Testing.

**Spec:** `docs/plan.md` sections 7 (gotchas), 8 "Custom targets (code)", 9 (version managers), 11 (admin confirm). `everclean.sh` in `docs/reference/` for the behavior being ported.

## Global Constraints

- All earlier constraints hold. Nothing is removed without the confirmation view; locked and in-use items are never removed.
- Tool items exist only when the tool is installed and (Docker) running; otherwise no item, no error.
- Tiers and flags from spec section 8: npm, pnpm, go.modcache, cargo.registry `redownload`; ios.simulators `regenerates`; ios.runtimes `redownload` + `heavy`, one item per runtime; ios.dyld `regenerates` + `needsAdmin`, one item per runtime folder; docker.buildcache `regenerates`; docker.images `dataLoss`; versions (fvm, nvm, rustup) `redownload` + `heavy`, one item per version.
- Locked versions (nvm current and default, fvm global, rustup active and default) get state `.locked(reason)` and are never planned. Reason text: `Active Node version`, `nvm default`, `fvm global`, `Active Rust toolchain`, `rustup default`.
- Commands from spec section 7, verbatim: `npm cache clean --force` then remove `~/.npm/_npx`; `pnpm store prune`; `go clean -modcache`; Cargo: remove `~/.cargo/registry/cache` and `~/.cargo/registry/src`, keep `index`; `xcrun simctl delete unavailable` retried up to 3 times, 3 s apart; `xcrun simctl runtime delete <uuid>`; `docker builder prune -a -f`; `docker container prune -f` then `docker image prune -a -f` (never volumes); `fvm remove <version>`; `bash -c 'source "$NVM_DIR/nvm.sh"; nvm uninstall <version>'`; `rustup toolchain uninstall <name>`.
- Admin delete: the app runs the bundled CLI as root through `osascript -e 'do shell script "<quoted phew> admin-delete-dyld <quoted path>…" with administrator privileges'`. `phew admin-delete-dyld` accepts only paths inside `/Library/Developer/CoreSimulator/Caches/dyld`, checked with `PathGuard`, deleted by enumeration. One admin prompt per clean, never per item.
- Pinned versions are found in the configured project roots with the M3 prune list: `.fvmrc` (`{"flutter": "x"}`), `.fvm/fvm_config.json` (`flutterSdkVersion`), `.nvmrc` (prefix match: `20` matches `20.11.0`), `rust-toolchain.toml` (`channel = "x"`) and `rust-toolchain`. A project with two pin files for the same tool counts once.
- Fixtures for tools not installed on the author's Mac (simctl with runtimes, Docker running) are hand-written from the formats in spec section 7 and marked `// synthetic`. Tests that call real tools run only with `PHEW_REAL_TOOLS=1`.

## Review Focus

1. A version used by a project (pinned) but not active: shown with "used by N projects" and not preselected; cleaning it still asks, with the projects listed in the confirm view. Test in Task 6.
2. Docker installed but not running: no Docker items, no error, scan time not blocked (each docker call has a 10 s timeout). Test in Task 4.
3. Admin prompt cancelled by the user: dyld items end as "skipped: admin password not given", nothing else fails. Test in Task 5.
4. A runtime with booted simulators: in use, not planned. Test in Task 5.
5. A command that fails (non-zero exit): the item records the stderr first line as the failure; the measured value still comes from re-measuring. Test in Task 1.

### Task 1: Removal kinds in the Executor

**Files:**
- Modify: `Sources/PhewCore/Models/Item.swift`, `Sources/PhewCore/Clean/Executor.swift`, `Sources/PhewCore/Clean/CleanPlan.swift`
- Test: `Tests/PhewCoreTests/RemovalTests.swift`

**Interfaces:**
- Produces:
  - `public enum Step: Codable, Sendable, Equatable { case run([String]); case remove(URL); case retry(times: Int, delaySeconds: Int, [String]) }` (`run` is `[executable, args…]` through `Shell.run` with a 10-minute timeout; `remove` deletes one path through the item's `PathGuard`, used for `~/.npm/_npx` and the Cargo folders; `retry` runs the command until it exits 0, used for `simctl delete unavailable`).
  - `public enum Removal: Codable, Sendable, Equatable { case paths; case steps([Step]); case adminDyld }`
  - `public enum Measure: Codable, Sendable, Equatable { case paths; case docker; case runtime(uuid: String) }`
  - `ItemState.locked(String)`.
  - `Item` gains `public var removal: Removal = .paths`, `public var measure: Measure = .paths`, `public var note: String? = nil` (for "used by 2 projects"). Codable keeps decoding old caches (missing keys = defaults).
  - `Planner.skipReason`: `.locked(reason)` -> `"\(reason). Phew won't remove it."`.
  - `Executor` takes `runCommand: @Sendable ([String]) async -> ShellResult?` (default `Shell.run` with timeout) and `dockerReclaimable: @Sendable () async -> Int64?` for injection.
- Behavior: `.steps` runs each step in order; the first failing step records `"<command>: <first stderr line>"` and stops that item. Measured = before minus after over `urls` for `.paths` measure; for `.docker`, before minus after of `dockerReclaimable` for the item's kind.
