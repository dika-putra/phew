# M3 Project Scanner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Find projects under the configured roots, list their build and dependency folders as cleanable items, and only offer folders that git ignores and that hold no tracked file.

**Architecture:** `ProjectRules` (data) says which marker files make a folder a project and which artifacts it owns. `ProjectWalker` walks the roots once, evaluates every rule on every folder, and groups artifacts under the outermost project. `GitSafety` drops artifacts that git tracks or does not ignore. `ProjectScanner` turns what is left into ordinary `Item`s (one per artifact), so `Planner` and `Executor` from M2 clean them unchanged.

**Tech Stack:** Swift 6, macOS 14+, Swift Testing, `git` through `Shell`.

**Spec:** `docs/plan.md` (sections 2 "Projects inside projects", 4 dormant rule, 6 rule 7, 7 prune list, 8 "Project rules", 10 `projectRoots`, 12)

## Global Constraints

- All M1 and M2 constraints still hold.
- An artifact is offered only when (a) its project marker matched, and (b) when the project is inside a git repo: `git check-ignore` reports the artifact path as ignored AND `git ls-files -- <artifact>` is empty. When git is missing or fails, the artifact is skipped with reason "Couldn't check git status".
- Generic names (`build`, `dist`, `vendor`, `target`, `bin`, `obj`, `deps`) are never artifacts without their rule's marker.
- WordPress: only `wp-content/cache` and `wp-content/upgrade`. Never `uploads`, `plugins`, `themes`. Laravel: never `storage/app`.
- Laravel and WordPress artifact folders are cleaned by contents (folder kept), and a child named `.gitignore` is never deleted (Laravel ships tracked `.gitignore` files there).
- Prune list (never descended into): `node_modules build .dart_tool target dist .next .nuxt .output .svelte-kit .turbo .git vendor .venv venv Pods .build .gradle .terraform _build deps obj bin .opencode .claude .cursor .windsurf .aider .continue .codeium`, any folder containing `pyvenv.cfg`, and symlinks.
- Dormant: newest file modification in the project (outside pruned folders) is older than `dormantDays` (config, default 14). Project items are preselected only when dormant and the tier rule allows it.
- Item ids: `projects:<artifact absolute path>`. Group `Projects`.

## Review Focus

1. A project whose `vendor/` or `build/` is committed to git (or force-added files inside an ignored folder): never offered. Test in Task 4.
2. A Flutter app with `ios/Pods`, `android/app/build`, `android/.gradle`: all grouped under the Flutter project and found even though `build` is pruned at the Flutter root. Test in Task 3.
3. A root that holds tens of thousands of folders inside `node_modules`: the walk never enters them. Test in Task 3 (walker never reports entries under a pruned folder).
4. A project root folder that is unreadable: the walk continues with other roots and reports it. Test in Task 3.
5. A folder that matches two stacks (Laravel plus Node): artifacts of both, each listed once. Test in Task 3.

### Task 3: ProjectWalker

**Files:**
- Create: `Sources/PhewCore/Projects/ProjectWalker.swift`, `Tests/PhewCoreTests/ProjectWalkerTests.swift`

**Interfaces:**
- Consumes: `ProjectRules`.
- Produces:
  - `public struct FoundArtifact: Sendable, Equatable { url: URL; tier: Tier; contents: Bool; files: [URL] }` (`files` set only for `files(in:suffix:)`, `contents` true for `.contents`).
  - `public struct FoundProject: Sendable { root: URL; stacks: [String]; artifacts: [FoundArtifact]; lastModified: Date? }`
  - `public struct WalkResult: Sendable { projects: [FoundProject]; unreadable: [URL] }`
  - `public enum ProjectWalker { static func walk(roots: [URL]) -> WalkResult }`
- Algorithm: depth-first over folders with `FileManager.enumerator` (no symlink following), `skipDescendants()` on pruned names and on folders holding `pyvenv.cfg`. For each visited folder, `ProjectRules.matching`; resolve its artifacts relative to that folder (only existing ones). A folder that matches becomes a project unless an ancestor already is one; then its stacks and artifacts join the outermost project. Artifacts are de-duplicated by path. `recursive(name)` artifacts are collected by the same walk: a pruned-free folder named `name` below a project that has that rule. `lastModified` is the newest `contentModificationDate` of files visited in that project. Unreadable folders go to `unreadable` and the walk continues.

### Task 4: GitSafety

**Files:**
- Create: `Sources/PhewCore/Projects/GitSafety.swift`, `Tests/PhewCoreTests/GitSafetyTests.swift`

**Interfaces:**
- Consumes: `Shell`, `FoundArtifact`.
- Produces: `public enum GitVerdict: Sendable, Equatable { case allowed, tracked, notIgnored, unknown }` and `public enum GitSafety { static func check(_ urls: [URL]) async -> [URL: GitVerdict] }`.
- Groups urls by repo (nearest ancestor with a `.git` folder or file). No repo: `.allowed`. Per repo, one `git -C <repo> check-ignore --stdin` (paths relative to the repo, one per line, via a temp file as stdin: `Shell` has no stdin parameter, so run `/bin/sh -c 'git -C "$0" check-ignore --stdin < "$1"'`) and one `git -C <repo> ls-files -z -- <paths>`. Verdict: listed by ls-files -> `.tracked`; not reported by check-ignore -> `.notIgnored`; git missing or exit code other than 0/1 -> `.unknown`; else `.allowed`. For `contents` and `files` artifacts the children are what gets checked, so the caller passes the child urls.
