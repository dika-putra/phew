# M2 Scan and Clean Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure every path target, plan a clean, delete safely, and report only measured results, usable from `phew scan` and `phew clean`.

**Architecture:** `Scanner` turns `PathTarget`s into `Item`s. `Planner` turns selected items into a `CleanPlan`, leaving in-use items out with a reason. `Executor` deletes through a per-target `PathGuard`, rechecks running apps right before each item, re-measures, and returns a `Receipt`. The CLI is a thin layer; the app (M4) reuses the same three types.

**Tech Stack:** Swift 6, macOS 14+, swift-argument-parser, Swift Testing, AppKit (`NSWorkspace`) for running apps.

**Spec:** `docs/plan.md` (sections 4, 5, 6, 7, 8, 11 "Clean flow", 12)

## Global Constraints

- All M1 constraints still hold (see `docs/superpowers/plans/2026-10-21-m1-core.md`).
- Safety rules 1 to 8 of spec section 6 are hard requirements. Rule 1: the receipt reports measured deltas only.
- Deletes are permanent (`FileManager.removeItem`), never to the Trash.
- Delete children by enumeration including hidden entries. Never a glob.
- In-use items are never cleaned. They show the app name and the message "<App> is running. Quit <App> to clean <title>." In the receipt they are "skipped, in use", not failures.
- Preselection: `regenerates` or `redownload`, and none of `heavy`, `needsAdmin`, `optIn`.
- Phew's own cache folder `~/Library/Caches/com.dikaputra.phew` is never part of `macos.caches`.
- Tests use temp folders and an injected home. Nothing in tests touches the real home.

## Review Focus

1. A `contents` target whose folder holds folders owned by other targets (`~/Library/Caches/Homebrew` inside `macos.caches`): those must be neither counted nor deleted. Test in Task 3 and Task 5.
2. A file that cannot be deleted (locked with `chflags uchg`, or a read-only parent): the item records a failure with the path, other paths and items continue, the measured value reflects what really went. Test in Task 5.
3. An app that starts between plan and execute: item becomes "skipped, in use". Test in Task 5.
4. A symlink inside a target folder pointing outside it: the link is removed, the target is untouched. Test in Task 5.
5. `phew clean` with an unknown id, or with no TTY and no `--yes`: clear error, nothing deleted, non-zero exit. Test in Task 7.

### Task 3: Item and Scanner

**Interfaces:**
- Consumes: `PathTarget`, `DiskSize`, `RunningCheck`, `expandTilde`.
- Produces:
  - `public enum ItemState: Sendable, Equatable { case ready, inUse(app: String), unreadable }`
  - `public struct Item: Sendable, Identifiable, Equatable { id: String; target: PathTarget; urls: [URL]; bytes: Int64; lastUsed: Date?; state: ItemState; var preselected: Bool }`. `urls` are what gets deleted: for a normal target the existing paths; for a `contents` target the children of each path minus excluded ones. `preselected` follows the Global Constraints rule.
  - `public struct Scanner: Sendable { init(home: URL = <home>, running: RunningCheck = .live); func scan(_ targets: [PathTarget]) async -> [Item] }`. Targets with no existing path produce no item. Items are returned in target order. Sizing runs concurrently per target (`withTaskGroup`).

  - `state`: `.inUse` when `running.firstRunning(target.skipIfRunning)` is non-nil; else `.unreadable` when every path is unreadable; else `.ready`.
  - `lastUsed`: the latest `contentModificationDate` of the item's paths (the paths themselves, not a deep walk).

### Task 5: Executor and Receipt

**Files:**
- Create: `Sources/PhewCore/Clean/Receipt.swift`, `Sources/PhewCore/Clean/Executor.swift`, `Tests/PhewCoreTests/ExecutorTests.swift`

**Interfaces:**
- Consumes: `CleanPlan`, `Item`, `PathGuard`, `DiskSize`, `RunningCheck`, `expandTilde`.
- Produces:
  - `public struct ReceiptEntry: Sendable, Equatable { itemID: String; title: String; claimed: Int64; measured: Int64; failures: [String]; skippedReason: String? }`
  - `public struct Receipt: Sendable { entries: [ReceiptEntry]; freeBefore: Int64; freeAfter: Int64; var measuredTotal: Int64; var mismatches: [ReceiptEntry] }`. A mismatch is `|claimed - measured| > max(1 MiB, claimed / 20)` for an entry that was not skipped.
  - `public struct Executor: Sendable { init(home: URL = <home>, running: RunningCheck = .live); func execute(_ plan: CleanPlan, progress: @Sendable (String) -> Void = { _ in }) async -> Receipt }`. Plan's skipped items become entries with `skippedReason`.
- Per item, in order:
  1. Recheck `running`; if in use, skip with the Planner's message.
  2. Build `PathGuard(allowedRoots: target.paths expanded, home: home)` (one guard per target, from the M1 review).
  3. For each URL: `guard.check(url)`, then `FileManager.removeItem(at:)`. On error, record `"<path>: <localizedDescription>"` and continue.
  4. `measured = item.bytes - sum(DiskSize.allocated(url).bytes for url in item.urls)` (a URL that is gone counts 0), floored at 0.
- `freeBefore` and `freeAfter` from `DiskSize.available(for: home)`.
