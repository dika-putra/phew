# M4 Menu Bar App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A menu bar app (`Phew.app`) that shows free space and what can be cleaned, cleans one item or a selection from the popover after a confirmation, and warns when space runs low.

**Architecture:** A third SwiftPM target `PhewApp` (SwiftUI `MenuBarExtra`, `.window` style) on top of `PhewCore`. Logic the UI needs but that has no UI (summary, cache, alert state, dev-server check) goes into `PhewCore` with tests. `AppModel` (`@Observable`, `@MainActor`) in the app target owns state and calls core. `make app` builds `Phew.app` from SwiftPM output: Info.plist with `LSUIElement`, the `phew` CLI inside `Contents/MacOS`, ad-hoc signature. No Xcode project.

**Tech Stack:** Swift 6, SwiftUI, macOS 14+, `MenuBarExtra`, `NSBackgroundActivityScheduler`, `UNUserNotificationCenter`, `SMAppService`, Swift Testing.

**Spec:** `docs/plan.md` sections 2, 4, 11 (all of it), 12 (install from the app), 14 (M4 row); preview mockup agreed in chat (Home, Detail, Confirm, Receipt, Settings, Notification).

## Global Constraints

- All earlier constraints still hold. The app never deletes without the confirmation view, and never in the background.
- Bundle id `com.dikaputra.phew`. Display name `Phew`. Version from `AppInfo.version`; build number `1`.
- Popover width 360 pt. Light and dark follow the system; settings has System, Light, Dark (`preferredColorScheme`). Colors: system semantic colors only (`.green`, `.blue`, `.red`, `.orange`, `.purple`, `.secondary`), which adapt to dark mode.
- Tier colors: Regenerates green, Redownload blue, Data loss red. In-use badge orange. FDA badge purple.
- Background scan: `NSBackgroundActivityScheduler`, identifier `com.dikaputra.phew.scan`, interval 2 hours, tolerance 10 minutes. Refresh button runs the same scan now. One scan at a time.
- Scan cache: `~/Library/Caches/com.dikaputra.phew/scan.json`.
- Low space alert: default on, 20 GB, checked every 15 minutes and after each scan; notifies once per drop, re-arms above threshold plus 5 GB. Text: `Only <X> left. Phew can free about <Y>.` (Y excludes `dataLoss` and `optIn` items).
- Copy (exact): receipt headline `Phew. <X> freed.`; in-use info `<App> is running. Quit <App> to clean <Title>.`; confirmation note `Deleted for good, not moved to the Trash.`; data loss line `Deletes data you can't get back.`
- About: `Phew <version> (<build>)`, `by Dika Putra`, `View on GitHub` -> `https://github.com/dika-putra/phew`, `Report an issue` -> `https://github.com/dika-putra/phew/issues`.
- Install CLI: symlink `~/.local/bin/phew` -> `<app>/Contents/MacOS/phew`; refuse to overwrite a file that is not a symlink.

## Review Focus

1. A cached scan hours old, then Clean: files gone since the scan are not failures, files added since are not deleted unless inside a selected folder. Test in Task 1.
2. Popover closed in the middle of a clean: the clean finishes and the receipt is shown next time. Task 6 keeps the clean in `AppModel`, not in a view.
3. `node`/`vite`/`flutter` running in a project: that project's artifacts are "in use". Test in Task 4.
4. Disk hovering around the threshold: one notification, not one every 15 minutes. Test in Task 3.
5. App launched with no project roots and no cache: Home shows a usable empty state and an "Add project folder" button, not a spinner forever. Covered in Task 5's manual check.
